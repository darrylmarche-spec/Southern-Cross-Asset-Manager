Create a complete Flutter mobile app optimized for iOS devices (using Cupertino widgets for native iOS look and feel) that digitizes two Schindler checklists for escalators and moving walks: first, the “SCS Truss Large Overhaul Workflow” checklist (as a pre-commissioning workflow), followed by the “Commissioning Checklist” (document Q 43831124, Rev. 03). The app is for me and my team to track tasks across both checklists, fill in responses, add remarks, track durations/labor, and monitor progress. Use Flutter’s state management with Provider for simplicity. Store data locally with SQLite (via sqflite package) for multi-user sharing on the same device or across devices if synced manually; optionally integrate Firebase Realtime Database for real-time team collaboration if I add the config later.
Key features:
* User authentication: Simple login with usernames (e.g., “Darryl”, “TeamMember1”) and passwords stored in SQLite. Each user can view/edit their own checklists but see team progress.
* Project creation: Screen to enter customer details (Customer, Project Name, Location, Commission Number, Type of Escalator/Moving Walk, Date of Completion).
* Checklist navigation: Use a tabbed or accordion interface where the Overhaul Workflow appears first (as Section 0), followed by the Commissioning sections. All tasks are in sequence, but completed tasks disappear from the main screen and move to a separate “Completed” page accessible via a hot button in the navigation bar.
* Task details: For each task (from both checklists):
    * Display UID (if applicable), task name, description/reference (e.g., comments, r2c, SAIS refs).
    * For Overhaul tasks: Fields for Estimated Duration (pre-filled), Estimated Labor (pre-filled), Actual Duration, Actual Labor, Comments (pre-filled but editable), Status (checkbox to mark complete), Assigned To (user dropdown), Due Date.
    * For Commissioning tasks: Radio buttons or dropdown for responses: Yes, No, ✓ (positive), V (negative, record findings for correction, fails SAIS), O (negative, not part of SAIS), N/A. Plus text field for remarks, checkbox for completion.
    * When marked complete, task moves to “Completed” page automatically.
* Completed Page: Lists all completed tasks (from both checklists), sorted by completion date. Filters by section, user, date. “Print Report” button generates a printable/shareable PDF (use pdf package) with project details, tables of completed tasks (with all fields, totals for durations/labor summed), open items, remarks, and signatures section.
* Progress tracking: Dashboard showing % complete per section/project, with color-coding (green for done, red for issues with V/O or overdue).
* Export: Button to generate and share PDF of entire checklist status or just completed.
* iOS-specific: Use CupertinoPageScaffold, CupertinoNavigationBar, adaptive scrolling, and safe area insets. Ensure it runs well on iPhone screens (test with iOS simulator if possible).
* Error handling: Validate required fields, show alerts for incomplete items.
* Database: SQLite tables for projects, users, tasks (columns: project_id, section, item_uid, name, description, est_duration, est_labor, act_duration, act_labor, response, remarks, status, assigned_to, due_date, completed_by, completed_at).
